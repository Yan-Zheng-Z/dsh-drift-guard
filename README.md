# drift-guard

给 DSH 用的确定性偏离检查插件。在模型执行工具调用时，按固定规则检查它有没有偏离"已批准的计划"和"基本规则"，发现问题就记录下来、按级别提醒，必要时拦住那一次调用。

## v0.2.0

### 新增
- **提醒模型**：检测到问题时，在当次工具结果末尾追加提醒（第 1 级：重读计划；第 2 级：停下汇报）。同一信号有冷却，一次只发最高级的一条。
- **新信号**：S2 交替打转、S3 重复读取未修改文件、S4 计划进展停滞；S1（原样重复）只记日志，与 DSH 自带的 repeat-tool-reminder 分工。
- **交接收益比 R**：R = r·[(C−C₀)·N + D·L·C] / H，综合上下文大小、剩余工作量和近期偏离程度，R ≥ 1 时建议完成当前步骤后交接；门槛按 1、2、4、8 递增，上下文 ≥ 600k 时强制提醒。
- **敏感文件拦截**：.env、.ssh、凭据、私钥、浏览器配置等，工作区内外都拦截；示例文件（.env.example 等）放行；支持放行名单。
- **工作区外读取**：放行，但记录到日志以便审计。
- **配置界面**：所有阈值与名单可在 DSH 插件设置里修改。
- **子智能体**：计数按会话分开；子智能体的交接提醒不会发给子智能体本身。

### 已知限制
- 只检查带路径参数的文件工具，不解析 shell 命令中的路径。
- R 的参数（r、H、L）为初始估计，r 依据 DeepSeek 当前缓存定价，价格变动时需更新。
- token 数为 tokenMeter 估算值。

**全部检查都是确定性代码判断，不调用 LLM、不解析 shell 命令。** 规则 1、3、5 与 S1–S4、交接收益比 R 只记录/提醒，规则 2、4 会拦截那一次调用：

| 规则 | 行为 | 对模型的影响 |
| --- | --- | --- |
| 1. 越界写入 | 写入/编辑/删除的文件不在 `PLAN.md` 当前已批准阶段的清单里 → **记录提醒**，不拦截 | 无（可被 S1–S4 与 R 的提醒带出来） |
| 2. 工作区外写入 | 目标路径在会话工作区之外 → **拦截**，工具体不执行，原因作为工具错误返回 | 该次调用失败，模型收到原因 |
| 3. 打转（同一调用连续失败） | 同一工具、相同参数连续失败 3 次 → **记录提醒** | 无 |
| 4. 敏感读取 | 读取类工具的目标命中敏感名单（凭据/密钥类）→ **拦截**，不读内容；工作区内、外一视同仁 | 该次调用失败，模型收到原因与补救办法 |
| 5. 工作区外读取 | 读取工作区外的**不敏感**文件 → 只记一条 `outside-read` | 无 |

被规则 2、4 拦截的调用**不计入**规则 3 的计数（一条规则不喂出另一条）。

### S1–S4、S6 与交接收益比 R：分级提醒

在规则 1–5 之外，插件还观察五类"打转/停滞/漫游"信号，并算一个"该不该交接"的比值 R。命中后把一段提醒**追加到触发它的那次工具结果的末尾**（只追加、不改原文）：

| 信号 | 含义 | 默认阈值 |
| --- | --- | --- |
| S1 | 同一工具 + 相同参数 + 相同结果连续重复 | 4 次 |
| S2 | 两组"工具+参数"来回交替 | 6 轮 |
| S3 | 同一文件在内容未修改时被重复读取 | 3 次 |
| S4 | `PLAN.md` 已打勾步骤数（或 todo 完成数）连续多次没有增加 | 20 次调用 |
| S6 | 连续多次调用既没成功写文件、也没推进计划或 todo（"漫游"） | 12 次调用 |
| R | 交接收益比 ≥ 1（"继续做下去"的成本对比"交接"的成本） | 见下 |

#### 交接收益比 R

```
R = r · [ (C − C₀) · N + D · L · C ] / H
```

| 符号 | 含义 | 默认值 |
| --- | --- | --- |
| `C` | 主会话上下文规模（token）：优先读 `ctx.tokenMeter`；读不到、或测量值不是数字时按 `调用次数 × tokensPerCall` 估算 | — |
| `C₀` | 上下文基线；低于基线的部分不计入（`C − C₀` 取不小于 0） | `20000` |
| `N` | 剩余工作量（**调用次数**）= `PLAN.md` 未打勾项数 × 已完成项的平均调用数；没有可用计划、或一项都还没打勾（算不出平均）时取 `defaultN`；计划已全部打勾（`planComplete`）时为 0 | `20` |
| `D` | 当前偏离强度 `Σ wᵢ·e^(−Δcallsᵢ/decayCalls)`，权重 `wS1 = 0.5`、`wS2 = 1`、`wS3 = 0.5`、`wS4 = 1`、`wS6 = 1` | — |
| `L` | 每单位偏离强度预计浪费的调用次数（与 `N` 同为"次数"，两项量纲一致） | `5` |
| `H` | 一次交接的实际 token 成本 | `60000` |
| `r` | 把"浪费的调用次数 × 上下文规模"折算成钱的系数 | `0.02` |

`Δcallsᵢ` = 本次调用序号 − 该信号**最近一次"被评估、且条件仍成立"**的调用序号。条件成立期间它恒为 0（权重不衰减）；条件消失后才按 `decayCalls`（默认 20）指数衰减。"条件消失"包括计数被重置，也包括**这一次根本没评估该信号**——例如中间插入了写文件、搜索等别的工具调用，S3 就不会被认为"仍在打转"。

`r` 的来源：DeepSeek **缓存命中 ¥0.02 / 百万 token**（未命中 ¥1.00 / 百万 token，峰谷同比例）。`r` 与 `H` 只以比值 `r / H` 进入公式，所以**官方价格调整时要同步改这两个值**（例如未命中价翻倍，就把 `r` 也翻倍），否则交接的临界点会跟着漂移。

**R 的提醒规则**（第 3 级，等同于"建议交接"）：

1. 第一次 `R ≥ 1` 就提醒；
2. 之后按**固定倍增门槛 1 → 2 → 4 → 8 …**：R 越过"下一个还没提醒过的门槛"才再提醒。一次跳过几层就记几层（R 从 1 直接涨到 8，中间 2、4 两层一并算已提醒过），避免在很短的间隔里连续提醒；
3. **硬上限**：`C ≥ capTokens`（默认 600000 token）时**首次触达单独提醒一次**；
4. 以上都还要过 `cooldownCalls` 的冷却；
5. R 只按**主会话自己**的调用与上下文计算，子智能体的命中不投递给它；

**参数非法时**：任一 R 参数不是有限数、或算出来的 R 不是有限数时，R 的判定按"不触发"处理，并在 `.drift/alerts.log` 里记一条（同一会话同一原因只记一条）。**硬上限独立于这个校验**：`capTokens` 非法时用默认 600000、`tokensPerCall` 非法时用默认 1500、调用次数不是有限数时按 0 计，所以配置坏掉时兜底提醒仍然有效。

**提醒级别**：首次触发是第 1 级（"重新读 `PLAN.md` 与用户原始要求"）；同一信号之后再触发是第 2 级（"停下来向用户汇报"）；R、以及"同时有 ≥2 个信号处于触发状态"是第 3 级。同一信号提醒过后要再过 `cooldownCalls` 次本会话的工具调用才能再提醒。S6 不参与"≥2 个信号"的计数，且在它触发期间压住 S4（两条判据嵌套，避免重复出声）。子智能体触发的第 3 级不追加给它自己，而是改写成第 2 级文案、挂到主会话的下一次工具结果上，并写明是哪个子智能体。

#### 第 3 级：交接提醒与完成判定

第 3 级的建议是**两段式**：先要求模型在本轮回复里明确告诉用户"建议现在交接"，等用户回复后再按交接模板写 `PROGRESS.md`（模板随那条合成通知一次性下发，每会话一次）。

- **交接起点**：每次第 3 级都记下提醒时间与当时的 `PROGRESS.md` 指纹（mtime+size）。
- **完成判定（主判据）**：`write` / `edit` / `ops_replace` **成功**且目标就是 `<工作区>/PROGRESS.md`。
- **完成判定（补充判据）**：`PROGRESS.md` 的指纹与提醒时不同——覆盖经 `ops_bash`/`pwsh` 写入与用户手改。代价是每次工具调用多一次 `stat`，误判方向是"多算完成"。
- **完成后的门槛**：把 R 的再提醒层级推到 `max(2, floor(log2(max(R,1)))+1)`，否则"由 ≥2 个信号触发"的那次第 3 级没有动这笔账，交接刚做完就会被同一个 R 再提醒。

这些判定都会显示在 `/drift` 的"交接状态"段里（时间、是否完成、依据、R 冷却剩余）。

## 安装（推荐：界面"添加插件"）

1. 打开 DSH 的插件页面，点**添加插件**。
2. 在输入框填入本目录的**绝对路径**，例如 `D:\dsh-plugins\drift-guard`。
   - 安装源选择框只影响注册表包名，本地路径不查注册表。
3. 安装完成后点**立即启用**。

界面安装由 plugin-manager 走 profile 的受管写入流程，**不需要手工改 `cordis.patch.yml` 或 `package.json`**。详见 [@deepseek-ai/dsh-plugin-manager 文档](https://www.npmjs.com/package/@deepseek-ai/dsh-plugin-manager) 的"添加插件"一节：它接受包名、Git 地址、压缩包或本地绝对路径。

本包的 `package.json` 声明了 `dsh.bundle.patch`（指向 `cordis.patch.yml`），plugin-manager 会把它识别为组合包；界面安装、GitHub 安装和本地路径安装都依赖这个声明。

### 打包后自检（改包必做）

`npm pack` 之后逐项确认（缺任何一项，界面"添加插件"都会以"这个包没有声明组合包"或加载失败告终）：

1. `package.json` 里有 `dsh.bundle.patch`，且它指向的文件**在 tar 包里**；
2. `cordis.patch.yml` 里是 `- insert:` 行，`name` 是包名 `dsh-drift-guard`（只写 `- id:` 不会新插入条目）；
3. `main` / `exports` 指向的 `lib/index.js` 在 tar 包里；
4. `files` 列的 7 个 `lib/*.js` 都在（少一个就会在运行时 import 失败）；
5. `package.json` 无 BOM，能被 `JSON.parse` 解析。

实测（v0.2.1，2026-10-17）：桌面板"添加插件"填 `github:YAN-ZHENG-Z/dsh-drift-guard#v0.2.1` 安装成功，profile 的 `cordis.yml` 挂载后插件当场生效（工作区 `.drift/alerts.log` 出现记录）。v0.2.2、v0.2.3 也照这 5 项检查过；v0.3.0 的 `lib/` 是 8 个文件（新增 `persist.js`）。

### 从 GitHub 安装（发布到仓库后）

```
github:YAN-ZHENG-Z/dsh-drift-guard          # 默认分支
```

### 手动安装（兜底，需要你确认后自行操作）

本机实测：通过 CLI 启动 profile 会重写 profile 的 `cordis.yml`（我用 `dsh web --help` 试过，被沙箱拦成 `EPERM`，路径是 `~/.dsh/profiles/web/cordis.yml`）。所以手工方式**不要动 `cordis.yml`**，改 `cordis.patch.yml`：

1. 备份：把 `~/.dsh/profiles/<profile>/cordis.patch.yml` 和 `package.json` 各复制一份带日期的副本。
2. 在 `cordis.patch.yml` 末尾追加：

   ```yaml
   - insert:
       - id: drift-guard
         name: "D:\\dsh-plugins\\drift-guard"
   ```

3. 让插件包能被解析：把本目录放进该 profile 的依赖（`"dsh-drift-guard": "file:D:/dsh-plugins/drift-guard"`），或在 patch 里用上一步的绝对路径让 loader 直接加载。
4. 重启 DSH。
5. 回滚：删除该条目，恢复备份文件，再重启。

## 使用

- **查看提醒**：在会话里输入 `/drift`，提醒列表以命令结果直接显示在对话里。报告里会一并给出**交接收益比 R 的构成**（`C` 及其来源、`C₀`、`N` 及来源、`D` 与各分量、`r`/`L`/`H`、硬上限是否触达、再提醒门槛）、**交接状态**（上次第 3 级提醒时间、是否完成与判定依据、R 提醒冷却还剩几次），以及"计划解析状态"——分三态：**没有 PLAN.md** / **有但格式不符（列出缺少的标记）** / **有且已全部完成**，不会静默失效。能读到时还会单列 `tokenMeter` 原始值。
- **日志**：每条提醒同时追加到 `<工作区>/.drift/alerts.log`（UTF-8，一行一条）；跨重启的计数状态在 `<工作区>/.drift/state/<sessionId>.json`。

## 配置

在插件配置（设置界面或 profile 的插件条目）里给键值即可，不填就用默认值：

| 键 | 默认值 | 含义 |
| --- | --- | --- |
| `s1Repeats` | `4` | S1：同一工具 + 相同参数 + 相同结果连续多少次 |
| `s2Alternations` | `6` | S2：两组调用交替多少轮 |
| `s3Reads` | `3` | S3：未修改的文件重复读多少次 |
| `s4IdleCalls` | `20` | S4：已打勾步骤数（或 todo 完成数）连续多少次调用没增加 |
| `s6RoamCalls` | `12` | S6：连续多少次调用既没成功写文件、也没推进计划或 todo |
| `failureRepeats` | `3` | 规则 3：同一调用连续失败多少次 |
| `cooldownCalls` | `10` | 同一信号提醒过后至少隔多少次调用才能再提醒 |
| `handoffRatio` | 见上 | 交接收益比 R 的参数组，逐键覆盖（见下表） |
| `useDefaultSensitive` | `true` | 是否使用内置敏感名单 |
| `useDefaultSensitiveAllow` | `true` | 是否使用内置放行名单（示例文件豁免） |
| `sensitive` | 见下 | **追加**到内置敏感名单的条目 |
| `sensitiveAllow` | 见下 | **追加**到内置放行名单的条目 |

`handoffRatio` 的 13 个键（每一项都可以单独覆盖，非法值——非有限数、低于下界——忽略并退回默认值）：

| 键 | 默认值 | 含义 |
| --- | --- | --- |
| `r` | `0.02` | 折算系数：把"浪费的调用次数 × 上下文规模"折算成钱的单价（来源见上文「交接收益比 R」） |
| `c0` | `20000` | 上下文基线 `C₀`（token） |
| `h` | `60000` | 一次交接的实际 token 成本 `H` |
| `l` | `5` | 每单位偏离强度预计浪费的调用次数 `L` |
| `decayCalls` | `20` | `D` 的指数衰减尺度（以调用次数计） |
| `wS1` / `wS2` / `wS3` / `wS4` / `wS6` | `0.5` / `1` / `0.5` / `1` / `1` | 各信号在 `D` 里的权重；设 0 等于把该信号从 `D` 里去掉 |
| `defaultN` | `20` | 没有可用计划、或算不出平均调用数时的剩余工作量 `N`；计划已全部打勾时为 0，不用这个默认值 |
| `tokensPerCall` | `1500` | 读不到 token 计量时，每次调用折算多少 token |
| `capTokens` | `600000` | 硬上限：上下文规模达到多少 token 就无条件提醒一次 |

**名单是"追加"语义**：`sensitive` / `sensitiveAllow` 里写的条目会**加在内置条目之后**；**空数组与未填写等价**，内置条目照常生效（设置界面保存时可能写入空数组，不能让默认保护被无声清空）。要停用内置条目，只能显式写 `useDefaultSensitive: false` / `useDefaultSensitiveAllow: false`。

> **代价（请知道）**：因为 `[]` 被当成"没配置"，所以"想清空内置名单"必须用开关，不能靠给空数组。这也是有意的取舍——空数组无法区分"界面保存时写进来的空值"和"用户真想清空"，而前者的代价（默认保护被静默清掉）更大。

内置敏感名单（19 条）：`.env`、`.env.*`、`.credentials*`、`id_rsa`、`id_ed25519`、`*.pem`、`*.key`、`*.pfx`、`*.p12`、`.ssh`、`.aws`、`.gnupg`、`.git-credentials`、`.netrc`、`.pypirc`、`.docker/config.json`、`Google/Chrome/User Data`、`Microsoft/Edge/User Data`、`Mozilla/Firefox/Profiles`。

内置放行名单（3 条）：`.env.example`、`.env.sample`、`.env.template`——文件名像凭据、内容却是给人看的示例文件。

条目写法（两份名单相同）：

- 不含 `/`、不含通配符 → 匹配**任一目录段或基名**（大小写不敏感）；
- 含 `*`/`?` → 只与基名做通配匹配；
- 含 `/` → 整串段序列，要求它在路径里**连续出现**（例如 `Microsoft/Edge/User Data`）；
- 以 `/` 结尾 → 按**目录前缀**匹配（该目录及其整个子树）。

其余固定值在代码里：`PLAN_FILE`（`PLAN.md`）、`ALERT_DIR` / `ALERT_LOG`（`.drift` / `alerts.log`）、`FILE_WRITE_TOOLS`（`write`、`edit`、`ops_replace`）。

## `PLAN.md` 怎么解析

- 按 Markdown 标题分块，标题里含 **`已批准`** 或 **`进行中`** 的块算"当前执行范围"；含 `待批准`、`已完成` 的块**不算**。
- 只在上述块内、**列表条目行**（`-`、`*`、`+`、`1.`）里提取路径。
- 只认路径形状的 token：含 `/`，或以 `.扩展名` 结尾。URL、盘符绝对路径（`C:\...`）、`~/...`、含 `*`/`?` 的 glob 一律忽略。
- **说明文字里的"像路径的词"也会被当成清单条目。** 提取只看这一行有没有路径形状的 token，不看它在句子里承担什么角色。所以"注意：本文件是夹具"这种说明性文字里，只要出现一个像文件名的词（`README.md`、`a.py` 这种裸文件名也算），它就会进清单。要避免这一点，说明文字里别写文件名，或把它改成不像路径的写法（例如写成"本文件"）。
- **条目一律转成小写后比较**（Windows 路径大小写不敏感），所以清单匹配是大小写不敏感的：清单里写 `readme.md` 能放行 `README.md`。
- 条目以 `/` 结尾视为目录，其子路径也算已批准（例如 `tmp/build/` 覆盖 `tmp/build/out.o`）。
- 条目里的相对路径只按**会话工作区根**解释。`PLAN.md` 只在工作区根目录读取，所以"`PLAN.md` 所在目录"恒等于工作区根，v0.2 的"双基准"退化为单基准。
- 写成 `acceptance/a.py` 这种"带一级子目录"的形式时，它的含义就是"工作区根下的 `acceptance/a.py`"。
- **迁移提示（v0.2.2 行为收紧）**：以前"把 `PLAN.md` 放在祖先目录、人在子目录里写计划"的用法不再生效——工作区里找不到 `PLAN.md` 就是 `absent`，`/drift` 会显示"工作区内没有 PLAN.md"。请把 `PLAN.md` 放到会话工作区的根目录。
- 整个文件解析不出任何"已批准/进行中"阶段，或这些阶段里一个路径都没有 → **规则 1 不生效**，`/drift` 会明确显示原因。

## `PLAN.md` 模板

复制下面这段改成自己的计划：

```markdown
# 我的任务

## 阶段 1：数据清洗 [已批准]

- [ ] 修改 `src/load.py`：读入原始数据
- [ ] 修改 `src/clean.py`：补缺失值处理
- [ ] 新建 `out/report.md`：输出清洗报告

## 阶段 2：出图 [待批准]

- [ ] 新建 `out/fig1.png`
```

- 阶段标题里带 `已批准` 或 `进行中`，该阶段列出的路径才算"当前执行范围"；`待批准`、`已完成` 的阶段不算。
  想临时扩大范围，把对应阶段的标题改成 `进行中` 即可。
- `[ ]` / `[x]` **不影响**哪些文件算已批准，只影响剩余工作量 `N` 的估算（未打勾项数 × 已完成项的平均调用数；全部打勾且确实使用复选框时 `N = 0`）。
- 说明文字里不要写文件名：裸文件名也会被算成清单条目（见已知限制第 9 条）。

## 已知限制（请先读）

1. **规则 2 拦不住 shell 里的路径。** 插件只检查带路径参数的文件工具（`write`、`edit`、`ops_replace`）。`ops_bash` / `pwsh` 里的 `> C:\...\x.txt` 看不到。这类写入由 DSH 自带沙箱兜底。
2. **规则 2 与 DSH 自带沙箱功能重叠。** 本机实测（workspace-write 档位）：
   - 往工作区外写：被沙箱拒绝（`Permission denied`），文件不会生成；
   - 工作区内写：沙箱一律放行。
   所以规则 2 的额外价值是**更早拦截 + 给模型可读的原因**，规则 1 才是沙箱完全没有的能力。
3. **符号链接/联接点不解析。** 路径判断是规范化字符串前缀比较，不调用 `realpath`。工作区内的符号链接指向工作区外时不会被识别。
4. **规则 1 只看写入目标，不看内容。** 不判断"改得对不对"，只判断"这个文件在不在清单里"。
5. **提醒去重。** 按"类型 + 工具 + 目标"去重：同一目标连续违规只提醒一次；中间有成功（规则 3）或路径改变后会再次提醒。`alerts.log` 与内存列表都会去重。
6. **不删除任何东西。** 插件不写工作区以外的文件，唯一的写入是工作区内的 `.drift/alerts.log`。
7. **规则 1 的清单是"宽"的。** 同一阶段里出现的任何路径都算已批准，插件不区分"要改的"和"只是提到的"。
8. **规则 1 的路径基准在 v0.2.2 收紧为单基准。** 条目只按会话工作区根解释；v0.2 里"再按 `PLAN.md` 所在目录解释一次"的双基准已退化（`PLAN.md` 现在只在工作区根读取），所以借上级目录计划放行的写法不再支持，见「`PLAN.md` 怎么解析」的迁移提示。
9. **计划正文里出现"像路径的词"会被算作清单条目，条目统一小写。** 两者都由测试断言固定，属于有意取宽而非缺陷：
   - 提取只看"这一行有没有路径形状的 token"，不看它在句子里的角色。所以已批准阶段的说明文字里顺口提到一个裸文件名（如 `README.md`），它也会进清单，导致本该报的越界**少报一次**。规避办法：说明文字里别写文件名。
   - 条目一律转小写后比较（Windows 路径大小写不敏感），清单匹配因此是大小写不敏感的。
10. **`glob` / `ops_glob` 的绝对路径 `pattern` 搜不到东西（本机实测结论，非规范保证）。** 在这台机器的这套 DSH 版本上实测：相对 pattern（`drift-guard/test/*.mjs`）正常返回文件；`../…`、盘符绝对路径（`C:/…/*.mjs`）**都返回 0 条且不报错**——glob 只在 `path`（默认会话工作区）之下搜索，绝对前缀不被当作搜索根（内置 `glob` 的官方类型注释也写着 "Absolute patterns are only permitted when the runner is configured to allow them"，与实测一致）。换版本后这个行为可能变，所以下面是按"实测成立"写的口径：
   - 因为绝对 pattern 本来就搜不到东西，插件**不**为它做"拦截这次搜索"（拦了也没有实际读取被阻止），只记一条 `outside-read`；
   - 但 pattern 的**字面前缀**（第一个通配符之前的部分；没有通配符时就是整串）仍是"要搜进去的位置"，所以它照常参与规则 4：`C:/x/.ssh/*.pem`、`C:/x/.env` 这类绝对模式会被拦下。**拦的理由是"目标落在敏感位置"，不是"这次搜索真会读到内容"**；
   - 相对 pattern（`**/*.env`、`.env`）一律视为在工作区里搜索，不触发本插件的任何规则。
11. **规则 1、3、5 与 S1–S6、R 只记录/提醒，只有规则 2、4 会真的拦住调用。** 这些提醒都是**追加到工具结果末尾**（不改原文），所以它会出现在触发它的那一步的模型可见内容里。
12. **R 里的上下文规模是估算值。** `ctx.tokenMeter` 给的是"当前请求正文的压力估算 / 复用最近一次 provider usage"，不是精确计费值；压缩上下文会改变 `C`，`R` 也随之跳变。读不到计量（服务没挂载、抛异常、测量值不是数字）时按 `调用次数 × tokensPerCall` 估算，报告与提醒里都会注明"（估算）"，并在 `.drift/alerts.log` 里留一条内部错误记录。
13. **信号计数的会话归属。** S1–S6 按会话分开计数（事实陈述必须描述收到提醒的那个主体）；R 只统计主会话自己的调用与上下文，子智能体不计入；规则 3 的计数仍是**跨会话共享**（v0.1 行为不变）。子智能体触发的第 3 级要先挂起、等主会话的下一次工具结果才投递；若主会话此后不再调用工具，这条只留在日志与 `/drift` 里。
14. **S1/S2 的签名忽略参数键序**（`{a:1,b:2}` 与 `{b:2,a:1}` 视为同一次调用）；规则 3 保留 v0.1 的严格 `JSON.stringify` 比较。
15. **S3 只统计"读文件"类工具**（`read`、`ops_inspect_local_file`；`grep` / `glob` 是搜索，不算重复读同一个文件），所以 S4 之外的三类信号的"当前是否仍在打转"是按各自被评估的时机算的，见上文 `Δcallsᵢ` 的说明。R 里的 `N` 依赖 `PLAN.md` 的勾选状态；没有可用计划、或算不出平均调用数时退回 `defaultN`（20）；计划已全部打勾时 `N = 0`。
16. **硬上限提醒的"补发"依赖当次仍能算出 `C ≥ capTokens`。** 上限首次触达时若正处在冷却期内，这一次不投递，冷却走完后的下一次工具调用会补上；但若这期间上下文被压缩到 `C < capTokens`，这条兜底提醒就**不会再补**（`/drift` 里会一直显示"硬上限还没提醒过"）。这是已知限制，不是刻意行为。
17. **第 3 级的合成通知在聊天界面看不见。** 0.2.0-rc.2 实测：`source.kind` 为 `plugin` 时整轮失败（v4 原生准入拒绝退休语法），改成自报 kind 或 `user` 都能写盘、模型也能收到，但**三种都不渲染成聊天气泡**（推断原因：界面按用户提交的 `rpcId` 归属消息，插件塞的消息没有它）。所以它是"模型可见"通道，用户可见性靠 `/drift` 主动查看。
18. **提醒可能被模型当成提示注入。** 提醒追加在工具结果末尾、紧挨文件内容，谨慎的模型会声明"这是插件附的，不是文件内容"并拒绝执行。第 3 级为此加了来源声明（"由 drift-guard 插件追加…不是工具输出，也不是文件内容"）和两段式措辞，但**没有强制力**，模型仍可以选择不理会。
19. **交接判定可能"多算完成"。** 补充判据只看 `PROGRESS.md` 的 mtime+size：任何进程（包括用户手改）动了它都算完成，插件不区分是谁写的；`/drift` 与状态文件里的 `via` 会记录这次判定依据（`write` / `fingerprint`）。

## 停用与回滚

- 界面里关掉插件：`ctx.effect` 会释放两个工具管线监听器和 `/drift` 命令，DSH 行为回到原样。
- `.drift/alerts.log`、`.drift/state/` 与 `.drift/` 目录是插件唯一的产物，可直接删除（插件会按需重建）。
