# drift-guard

给 DSH 用的确定性偏离检查插件。在模型执行工具调用时，按固定规则检查它有没有偏离"已批准的计划"和"基本规则"，发现问题就记录下来并让你看到。

**第一版只做三件事，不调用 LLM、不往模型上下文注入内容、不打断主会话：**

| 规则 | 行为 | 对模型的影响 |
| --- | --- | --- |
| 1. 越界写入 | 写入/编辑/删除的文件不在 `PLAN.md` 当前已批准阶段的清单里 → **记录提醒**，不拦截 | 无 |
| 2. 工作区外写入 | 目标路径在会话工作区之外 → **拦截**，工具体不执行，并把原因作为工具错误返回 | 该次调用失败，模型收到原因 |
| 3. 打转 | 同一工具、相同参数连续失败 3 次 → **记录提醒** | 无 |

被规则 2 拦截的调用**不计入**规则 3 的计数（一条规则不喂出另一条）。

## 安装（推荐：界面"添加插件"）

1. 打开 DSH 的插件页面，点**添加插件**。
2. 在输入框填入本目录的**绝对路径**，例如 `D:\dsh-plugins\drift-guard`。
   - 安装源选择框只影响注册表包名，本地路径不查注册表。
3. 安装完成后点**立即启用**。

界面安装由 plugin-manager 走 profile 的受管写入流程，**不需要手工改 `cordis.patch.yml` 或 `package.json`**。详见 [@deepseek-ai/dsh-plugin-manager 文档](https://www.npmjs.com/package/@deepseek-ai/dsh-plugin-manager) 的"添加插件"一节：它接受包名、Git 地址、压缩包或本地绝对路径。

### 从 GitHub 安装（发布到仓库后）

```
YAN-ZHENG-Z/dsh-drift-guard          # 默认分支
YAN-ZHENG-Z/dsh-drift-guard#v0.1.0   # 固定到某个 tag
```

上面两行就是"添加插件"输入框里可以直接填的内容。用 tag 写法更稳：默认分支会随仓库更新，tag 固定住版本。仓库发布后请确认 tag 名与实际打的 tag 一致（`git tag` 查看）。

### 手动安装（兜底，需要你确认后自行操作）

本机实测：通过 CLI 启动 profile 会重写 profile 的 `cordis.yml`（我用 `dsh web --help` 试过，被沙箱拦成 `EPERM`，路径是 `~/.dsh/profiles/web/cordis.yml`）。所以手工方式**不要动 `cordis.yml`**，改 `cordis.patch.yml`：

1. 备份：把 `~/.dsh/profiles/<profile>/cordis.patch.yml` 和 `package.json` 各复制一份带日期的副本。
2. 在 `cordis.patch.yml` 末尾追加：

   ```yaml
   - id: drift-guard
     name: "D:\\dsh-plugins\\drift-guard"
   ```

3. 让插件包能被解析：把本目录放进该 profile 的依赖（`"dsh-drift-guard": "file:D:/dsh-plugins/drift-guard"`），或在 patch 里用上一步的绝对路径让 loader 直接加载。
4. 重启 DSH。
5. 回滚：删除该条目，恢复备份文件，再重启。

## 使用

- **查看提醒**：在会话里输入 `/drift`，提醒列表以命令结果直接显示在对话里。命令会一并说明"计划解析状态"，包括**未找到可解析的计划**这一情况（不会静默失效）。
- **日志**：每条提醒同时追加到 `<工作区>/.drift/alerts.log`（UTF-8，一行一条）。

## 配置

改 `lib/index.js` 顶部的常量即可（第一版不引入配置文件）：

| 常量 | 默认值 | 含义 |
| --- | --- | --- |
| `PLAN_FILE` | `PLAN.md` | 固定读工作区根目录下的这个文件 |
| `ALERT_DIR` / `ALERT_LOG` | `.drift` / `alerts.log` | 提醒日志位置 |
| `REPEAT_THRESHOLD` | `3` | 规则 3 的阈值 |
| `FILE_WRITE_TOOLS` | `write`、`edit`、`ops_replace` | 参与规则 1、2 检查的工具名 |

## `PLAN.md` 怎么解析

- 按 Markdown 标题分块，标题里含 **`已批准`** 或 **`进行中`** 的块算"当前执行范围"；含 `待批准`、`已完成` 的块**不算**。
- 只在上述块内、**列表条目行**（`-`、`*`、`+`、`1.`）里提取路径。
- 只认路径形状的 token：含 `/`，或以 `.扩展名` 结尾。URL、盘符绝对路径（`C:\...`）、`~/...`、含 `*`/`?` 的 glob 一律忽略。
- **说明文字里的"像路径的词"也会被当成清单条目。** 提取只看这一行有没有路径形状的 token，不看它在句子里承担什么角色。所以"注意：本文件是夹具"这种说明性文字里，只要出现一个像文件名的词（`README.md`、`a.py` 这种裸文件名也算），它就会进清单。要避免这一点，说明文字里别写文件名，或把它改成不像路径的写法（例如写成"本文件"）。
- **条目一律转成小写后比较**（Windows 路径大小写不敏感），所以清单匹配是大小写不敏感的：清单里写 `readme.md` 能放行 `README.md`。
- 条目以 `/` 结尾视为目录，其子路径也算已批准（例如 `tmp/build/` 覆盖 `tmp/build/out.o`）。
- 条目里的相对路径按**两种基准**解释，任一命中即算已批准：会话工作区根（本项目的写法），以及 `PLAN.md` 所在目录（计划放在祖先目录时的写法）。写成 `acceptance/a.py` 这种"带一级子目录"的形式时，只有基准正确才命中。
- 整个文件解析不出任何"已批准/进行中"阶段，或这些阶段里一个路径都没有 → **规则 1 不生效**，`/drift` 会明确显示原因。

## 已知限制（请先读）

1. **规则 2 拦不住 shell 里的路径。** 插件只检查带路径参数的文件工具（`write`、`edit`、`ops_replace`）。`ops_bash` / `pwsh` 里的 `> C:\...\x.txt` 看不到。这类写入由 DSH 自带沙箱兜底。
2. **规则 2 与 DSH 自带沙箱功能重叠。** 本机实测（workspace-write 档位）：
   - 往工作区外写：被沙箱拒绝（`Permission denied`），文件不会生成；
   - 工作区内写：沙箱一律放行。
   所以规则 2 的额外价值是**更早拦截 + 给模型可读的原因**，规则 1 才是沙箱完全没有的能力。
3. **符号链接/联接点不解析。** 路径判断是规范化字符串前缀比较，不调用 `realpath`。工作区内的符号链接指向工作区外时不会被识别。
4. **规则 1 只看写入目标，不看内容。** 不判断"改得对不对"，只判断"这个文件在不在清单里"。
5. **提醒去重。** 按"类型 + 工具 + 目标"去重：同一目标连续违规只提醒一次；中间有成功（规则 3）或路径改变后会再次提醒。`alerts.log` 与内存列表都会去重。
6. **不删除任何东西。** 插件不写工作区以外的文件，唯一的写入是工作区内的 `.drift/alerts.log`。
7. **规则 1 的清单是"宽"的。** 同一阶段里出现的任何路径都算已批准，插件不区分"要改的"和"只是提到的"。
8. **规则 1 的路径基准也是"宽"的。** 每个条目会按会话工作区根和 `PLAN.md` 所在目录各解释一次，任一命中即放行。所以清单条目写成相对路径时，可能比字面意思多覆盖一个位置（例如会话 cwd 恰好叫 `acceptance` 时，`acceptance/a.py` 与 `a.py` 指的是同一个文件）。宁可少提醒，也不误报——误报会让人干脆忽略提醒。
9. **计划正文里出现"像路径的词"会被算作清单条目，条目统一小写。** 两者都由测试断言固定，属于有意取宽而非缺陷：
   - 提取只看"这一行有没有路径形状的 token"，不看它在句子里的角色。所以已批准阶段的说明文字里顺口提到一个裸文件名（如 `README.md`），它也会进清单，导致本该报的越界**少报一次**。规避办法：说明文字里别写文件名。
   - 条目一律转小写后比较（Windows 路径大小写不敏感），清单匹配因此是大小写不敏感的。

## 停用与回滚

- 界面里关掉插件：`ctx.effect` 会释放两个工具管线监听器和 `/drift` 命令，DSH 行为回到原样。
- `.drift/alerts.log` 与 `.drift/` 目录是插件唯一的产物，可直接删除。

## 开发

```
node --check lib/index.js     # 语法检查
node test/smoke.mjs           # 纯函数冒烟测试（71 项，不需要模型、不需要 DSH 实例）
```

`test/smoke.mjs` 从任意目录运行都可以：它按脚本自身位置解析插件路径，所有"工作区"都是运行时在系统临时目录里造出来的，用完即删，不写仓库。`test/fixtures/` 里是给人看的样例夹具（一份模仿分阶段格式的 `PLAN.md` 和几个样本文件），冒烟测试会直接读它来保证夹具格式与解析器长期一致。

`lib/index.js` 同时导出纯函数（`parsePlan`、`classifyWrite`、`failureDecision`、`alertLine`、`inspectPlan`、`formatDriftReport`、`resolvePath`、`isOutsideWorkspace`、`isApproved`），测试直接调用它们，覆盖路径解析、计划解析、两条规则判定、阈值与去重文案。
